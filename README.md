# 订单 / 发票比对工具

## 快速开始

### 方式一：图形界面（推荐）

1. 打开 `dist\订单发票比对工具\订单发票比对工具.exe`  
   （或本机执行 `python reconcile_gui.py`）
2. 选择**订单数据**、**发票数据**原始 Excel
3. 指定**结果保存路径**
4. 点击「导出比对结果」

### 方式二：命令行（默认读项目内样例文件）

```bash
python reconcile.py
```

默认读取 `datas/订单数据3.xlsx`、`datas/发票数据3.xlsx`，输出 `datas/比对结果.xlsx`。  
（`datas/` 下业务 Excel 不提交 GitHub；空白模板在 `templates/`。）

### 依赖

```bash
pip install -r requirements.txt
```

主要依赖：`openpyxl`（读写 Excel）。界面使用 Python 自带的 `tkinter`，无需额外安装。

## 输入文件要求

程序按**表头**自动定位工作表，不依赖固定 sheet 名。

| 文件 | 必要列 | 说明 |
|------|--------|------|
| 订单数据 | `交货日期`、`型号`、`数量`、`用户价格` | 常见还有：订单号、接单日期、订单状态、用户等 |
| 发票数据 | `开票日期`、`规格型号`、`数量`、`单价` | 常见还有：发票号码、价税合计、购买方名称等 |

### 预处理（脚本自动完成）

1. **订单**  
   - 增加「价格合计」= `数量 × 用户价格`  
   - 「E率」= `round(((价格 / 1.13 / E价) - 1) × 100)`，**整数百分比**（不留小数；价格或 E价缺失、E价为 0 时为空）  
   - `交货日期`、`接单日期` 只保留年月日（去掉时分秒）  
   - 按型号、交货日期升序  
2. **发票**  
   - 「数量」「单价」由文本转为数字：数量保留整数，单价保留 2 位小数  
   - 增加「含税单价」= `单价 × 1.13`（基于转换后的单价）  
   - `开票日期` 只保留年月日（去掉时分秒）  
   - 按规格型号、开票日期升序  
3. **配对前排除（不删除）**  
   - 发票「数量」为负数，或「发票状态」含 `已红冲-全额` → **不参与比对**（数据保留）  
   - 「发票状态」为 `已红冲-部分` → **仍参与比对**  
   - 排除行仍保留在预处理结果与最终比对结果中，状态为「不参与比对」  

> 注意：业务上「订单」与「发票」文件不要搞反。关联键是 **订单.型号 = 发票.规格型号**（大小写/空格不敏感）。

## 业务底层逻辑

两张表在业务上的角色与价格含义如下（后续规则与人工核对应以此为准）：

| 表 | 业务含义 | 关键价格字段 |
|----|----------|--------------|
| **订单表** | 经销商向其**上游**申请时的数据 | **用户价格** = 申请卖给客户的**含税单价** |
| **发票表** | 经销商**实际卖给客户**的开票信息 | **单价** = 实际卖给客户的**不含税单价**；预处理后的**含税单价**（`单价 × 1.13`）= 实际卖给客户的**含税单价** |

**价格合规要求（核心）：**

经销商实际销售给客户的含税单价，**不得高于**申请销售给客户的含税价格。即：

> 预处理后发票表的 **含税单价** ≤ 订单表的 **用户价格**

（实现比对/告警规则时，应以上述单向约束为准，而不仅是「两侧价格接近」。）

已配对场景下的价格状态细分：

| 匹配状态 | 规则 | 需人工 |
|----------|------|--------|
| 完全匹配 | \|用户价格 − 含税单价\| ≤ 0.02 | 否 |
| 实际售价高于申请价格 | 含税单价 > 用户价格 + 0.02 | 是 |
| 实际售价低于申请价格 | 含税单价 < 用户价格 − 0.02 | 是 |
| 价格缺失 | 用户价格或含税单价无法计算 | 是 |

## 发票查询周期与账期

| 参数 | 含义 |
|------|------|
| 发票查询周期 | 本次比对的发票时间范围（起始日、结束日） |
| 账期 | 发货后允许多久开票仍算正常，单位：天 |

**边界推算（自然月）：**

- 期初豁免截止日 = 起始日 + N 个月 − 1 天  
- 期末豁免起始日 = 结束日 − N 个月 + 1 天  

例：周期 2025-01-01～2025-12-31、账期 60 天 → 期初豁免截止 **2025-03-01**，期末豁免起始 **2025-11-02**。

| 情形 | 状态 | 需人工 | 问题偏向 |
|------|------|--------|----------|
| 开票日 ≤ 期初豁免截止且未配上订单 | 账期内无订单 | 否 | 发票无订单 |
| 交货日 ≥ 期末豁免起始且未配上发票 | 账期内待开票 | 否 | 订单未开票 |
| 豁免区外、订单未配上（含仅订单侧型号） | 订单未开票 | 否 | 订单未开票 |
| 豁免区外、发票未配上（含仅发票侧型号） | 发票无订单 | 否 | 发票无订单 |
| 同型号有等量对方但不满足先发货后开票 | 同型号开票早于发货 | 是 | 订单行→订单未开票；发票行→发票无订单 |
| 同型号无等量可配 | 同型号数量无法对齐 | 是 | 同上 |
| 本可配但候选已被占用 | 同型号行已被其他票/单占用 | 是 | **其他** |

结果表增加列 **「问题偏向」**，取值仅：`订单未开票` / `发票无订单` / `其他`（已配对行等可为空）。

### 核实优先级（筛选用）

用于判断「哪些需要同数据提供方沟通核实」。在「匹配明细」中按 **核实优先级** 筛选「高」或「中」即可（已不再单独输出沟通清单 sheet）。

| 核实优先级 | 匹配状态 |
|------------|----------|
| **高** | 实际售价高于申请价格；订单未开票；发票无订单；同型号开票早于发货；同型号数量无法对齐；同型号行已被其他票/单占用 |
| **中** | 数据异常；价格缺失 |
| **（空）** | 完全匹配；账期内待开票；账期内无订单；不参与比对；实际售价低于申请价格 |

未填查询周期时，按发票开票日最早/最晚日期所在月：起始=该月**月初第一天**，结束=该月**月末最后一天**；账期默认 **30** 天。GUI 中周期起止默认空，**选择发票文件后自动推断填入**，可再手动改。

## 比对规则

### 关联与硬约束

| 项 | 规则 |
|----|------|
| 关联键 | 订单.`型号` ↔ 发票.`规格型号`：去掉**全部空白**后 `casefold`（大小写、中间空格不敏感）；结果表仍显示原文 |
| 日期 | **交货日期 &lt; 开票日期**（严格早于；同一天不算可自动匹配） |
| 粒度 | 行级**一对一**（一条订单行最多配一张发票行） |

### 匹配优先级（同型号组内）

1. 数量完全相等，且满足日期硬约束  
2. 在候选中优先 `|用户价格 − 含税单价| ≤ 0.02`  
3. 仍有多条时：价格更接近优先，再按开票日期 FIFO  

### 状态判定（已锁定）

| 情形 | 匹配状态 | 是否需人工核对 |
|------|----------|----------------|
| 日期合法 + 数量相等 + \|用户价格−含税单价\| ≤ 0.02 | **完全匹配** | 否 |
| 同上，但存在多条等量候选（FIFO 取一条） | **完全匹配**，原因含 `MULTI_CAND` | 否 |
| 匹配键相同但原文仅大小写/空格不同 | **完全匹配**，原因含 `CASE_DIFF` / `SPACE_DIFF` | 否 |
| 已配对，含税单价 > 用户价格 + 0.02 | **实际售价高于申请价格**（`PRICE_OVER`） | **是** |
| 已配对，含税单价 < 用户价格 − 0.02 | **实际售价低于申请价格**（`PRICE_UNDER`） | **是** |
| 已配对，用户价格或含税单价无法计算 | **价格缺失** | **是** |
| 见「发票查询周期与账期」 | **账期内待开票 / 账期内无订单 / 同型号\*** 等 | 见上节 |
| 型号仅出现在订单（非豁免） | **订单未开票** | 否 |
| 型号仅出现在发票（非豁免） | **发票无订单** | 否 |
| 数量为负或状态含「已红冲-全额」 | **不参与比对**（数据保留；「已红冲-部分」仍参与） | 否 |
| 关键字段缺失/无法解析 | **数据异常** | **是** |

价格容差常量：`PRICE_TOLERANCE = 0.02`（见 `reconcile.py`）。

### 异议原因代码

| 代码 | 含义 |
|------|------|
| `MULTI_CAND` | 同型号多条等量候选，按规则取一条，可能配错（仍可算完全匹配） |
| `CASE_DIFF` | 型号大小写不一致（仍可算完全匹配，不强制人工） |
| `SPACE_DIFF` | 型号含空格差异（仍可算完全匹配，不强制人工） |
| `EXCL_NEG_QTY` | 发票数量为负，不参与比对 |
| `EXCL_RED_FLUSH` | 发票状态含「已红冲-全额」，不参与比对（「已红冲-部分」仍参与） |
| `PRICE_OVER` | 含税单价高于用户价格 → **实际售价高于申请价格**（违反「实际不得高于申请」） |
| `PRICE_UNDER` | 含税单价低于用户价格 → **实际售价低于申请价格** |
| `DATE_ORDER` | 违反「先订单/发货，后开票」 |
| `SAME_MODEL_UNMATCHED` | 同型号未能自动匹配 |
| `MODEL_QTY_GAP` | 该型号订单数量合计 ≠ 发票数量合计 |
| `QTY_POOL_HINT` | 型号级数量接近，疑似需拆分/合并后人工核对 |
| `ONLY_ORDER` / `ONLY_INVOICE` | 型号仅在一侧出现 |
| `STATUS_MISMATCH` | 如订单状态为「已开票」但未找到匹配发票 |
| `BAD_FIELD` | 型号/数量/日期等关键字段缺失或无法解析 |

### 暂未做的能力（二期可扩展）

- 一条订单拆成多张发票、或一张发票冲减多笔订单的**数量池冲减**  
- 当前以行级等量一对一为主；型号合计不平衡会写入 `MODEL_QTY_GAP` / `QTY_POOL_HINT` 提示人工处理

## 结果说明

输出文件（默认名 `比对结果.xlsx`）包含多个工作表：

| 工作表 | 内容 |
|--------|------|
| **匹配明细** | 全部比对行（含分区配色与核实优先级着色，见下「颜色规则」） |
| **型号汇总** | 按型号统计数量差、各状态行数 |
| **规则说明** | 规则摘要 + 颜色图例 |
| **预处理-订单 / 预处理-发票** | 带计算列、已排序的源数据副本 |

### 匹配明细列顺序（发票 → 订单 → 匹配结果；隐藏列保留可取消隐藏）

**1. 发票**（左→右）

数电发票号码、货物或应税劳务名称、规格型号、数量、含税单价、  
序号 / 发票代码 / 发票号码 / 单位 / 单价 / 金额 / 税率 / 税额 / 价税合计 / 发票状态 / 购买方名称 / 销方名称 / 备注（**隐藏**）、  
开票日期  

**2. 订单**（左→右）

交货日期、订单号、型号、数量、用户价格、E率、  
价格合计 / 价格 / E价 / 接单日期 / 订单状态 / 用户（**隐藏**）、  
战略标记、统计对象  

**3. 匹配结果**（顺序不变）

核实优先级、匹配状态、问题偏向、是否需人工核对、异议原因  

冻结在整段发票列之后，便于横滑对照订单与匹配结果。

### 匹配明细颜色规则

| 类型 | 规则 |
|------|------|
| 表头 | 发票可见绿底白字；发票其余浅绿深字；订单可见蓝底白字；订单其余浅蓝深字；匹配结果深紫白字 |
| 行底 | 核实「高」浅橙；「中」浅黄；数据异常浅红（优先）；空优先级不铺整行色 |
| 字体 | 核实高=橙红加粗；中=褐加粗；实际售价高于申请价格=红加粗；问题偏向「其他」=灰紫；异议原因=灰小字 |
| 不做 | 完全匹配不用绿字；不为每种状态单独设行色 |

筛沟通清单：在匹配明细对「核实优先级」筛选「高」或「中」。

### 匹配明细排序

1. 相同型号聚在一起（订单型号 / 发票规格型号）  
2. 组内按 **发生日** 时间线升序：有开票日用开票日；仅订单未开票则用交货日（再退接单日），使未配订单插入到对应时间位置而非沉底  
3. 同日再按另一侧日期、匹配状态稳定排序  
4. **不会**把「人工核对-未配对」单独置顶  

底色约定：

- 浅蓝：订单侧字段（非人工高亮行）  
- 浅黄：需人工核对  
- 浅红：数据异常

## 图形界面与打包

### 本机运行界面

```bash
python reconcile_gui.py
```

功能：界面为 `ui.html` Fluent 设计（经 pywebview / Edge WebView2 加载）；自选订单/发票与结果路径；「格式说明」与模板下载；深色终端日志与百分比进度；后台线程调用 `run_reconcile()`。目标机需具备 WebView2 运行时（Win10/11 通常已预装）。

### 生成可执行文件（拷贝到公司电脑）

目标环境参考：Windows 10 专业版、**x64**、约 8GB 内存。无需在目标机安装 Python。

```bash
# 或双击
build_exe.bat
```

产物目录：

```text
dist\订单发票比对工具\
  ├─ 订单发票比对工具.exe
  ├─ _internal\          ← 依赖与 templates，必须一起拷贝
  └─ 使用说明.txt
```

**请整夹拷贝**，不要只拷单个 exe。

### 杀软误报（360 等提示木马）

PyInstaller 生成的**未签名** exe 常被 360 / Defender 误报为木马，属常见现象，并非程序含毒。  
处理：将整个 `订单发票比对工具` 目录加入信任区；详见 `使用说明.txt` 第二节。  
根治需购买 Windows 代码签名证书并对 exe 签名。打包已关闭 UPX，并写入版本信息以降低部分误报。

重新打包配置见 `订单发票比对工具.spec`。

## Git / GitHub 推送

远程仓库：https://github.com/HaoZi0120/reconcliliation

本机若出现浏览器能打开 GitHub，但 `git push` 报 `Could not connect to server` / `Failed to connect to github.com:443`：多半是 **系统代理只对浏览器生效，Git 未走代理**。

当前环境系统代理一般为 `127.0.0.1:7897`（以「设置 → 代理」或代理软件端口为准）。推送前在 PowerShell 中执行：

```powershell
$env:Path += ";C:\Program Files\Git\cmd"
$env:HTTP_PROXY = "http://127.0.0.1:7897"
$env:HTTPS_PROXY = "http://127.0.0.1:7897"
cd d:\projects\reconciliation
git push
```

若希望长期生效（可选）：

```powershell
git config --global http.proxy http://127.0.0.1:7897
git config --global https.proxy http://127.0.0.1:7897
```

取消代理：

```powershell
git config --global --unset http.proxy
git config --global --unset https.proxy
```

说明：

- `datas/` 下业务 Excel 已由 `.gitignore` 忽略，不会上传；`templates/` 模板会提交。
- 若新开终端提示找不到 `git`，可先执行上方 `$env:Path += ...`，或重启 Cursor / 电脑后再试。
- 代理端口若与 `7897` 不同，请改成你本机实际端口。

## 命令行用法

CLI 使用**英文参数名**；选定发票后按开票日推断查询周期（最早开票月月初～最晚开票月月末），交互提示为中文文案，可回车确认或修改。GUI 界面标签为中文（发票查询周期、账期等）。

```bash
# 交互：推断周期 → 确认/修改 → 导出
python reconcile.py

# 指定文件
python reconcile.py --order 订单.xlsx --invoice 发票.xlsx --output 比对结果.xlsx

# 预先给出周期（仍会展示并进入确认，可改）
python reconcile.py --period-start 2025-01-01 --period-end 2025-12-31 --account-days 60

# 非交互：不询问，直接用推断或命令行已给的起止日
python reconcile.py --non-interactive --account-days 60
```

| 参数 | 说明 |
|------|------|
| `--order` | 订单 Excel，默认项目内样例 |
| `--invoice` | 发票 Excel，默认项目内样例 |
| `--output` | 输出路径，默认 `比对结果.xlsx` |
| `--period-start` | `YYYY-MM-DD`，可选 |
| `--period-end` | `YYYY-MM-DD`，可选（须与 start 成对） |
| `--account-days` | 账期天数，整数，默认 30 |
| `--non-interactive` | 不提示修改 |
| `--save-preprocess` | 额外写出预处理 xlsx |

Python API：

```python
from reconcile import run_reconcile

stats = run_reconcile(
    order_path="订单.xlsx",
    invoice_path="发票.xlsx",
    output_path="比对结果.xlsx",
    period_start=None,   # None=按发票开票日推断
    period_end=None,
    account_days=30,
)
```

`stats` 另含：`period_start`、`period_end`、`account_days`、`grace_invoice_until`、`grace_order_from`、`period_inferred` 等。

### 历史方案结论（便于回顾）

- 文件角色以**列含义**为准：含「交货日期/型号/用户价格」的是订单；含「开票日期/规格型号/单价」的是发票。  
- 价格关系在样例数据中较稳定：`用户价格 ≈ 单价 × 1.13`（即含税单价），故价格超差单独标人工核对。  
- 同型号常有多行，不能只用「型号 + 日期 FIFO」；需 **数量优先 + 价格校验**。  
- 不确定数据一律标人工核对并写明原因，避免误报「完全匹配」。
